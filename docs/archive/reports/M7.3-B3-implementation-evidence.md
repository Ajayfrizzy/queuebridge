Local uncommitted candidate on feature/m7-3-hardening, base 5d2e5ea. The accepted B2 measurements were 159,495 gzip bytes for the shared entry and 159,635 including registration on join and ticket. The maximum permitted size is 99,999 B.

### Offline and installation

A separate worker-enabled join observed the local QR encoder and visitor route chunks among install requests. Activation contained zero landing assets. All six warm join JS requests transferred zero bytes. Offline join rendered the seeded facility. The first QR request on an offline ticket produced the recovery QR and an offline reload reopened the ticket. A dedicated browser regression checks keyboard focus remains on the QR toggle. In the first diagnostic fixture the ticket lacked a recovery-key control; the repeat used the test encryption configuration and verified the control before disconnecting.

The build listed 47 precache entries (958.21 KiB). An independent cold static-origin install served the same clean assets with forced gzip and no HTTP caching. From the worker script request to control it observed 49 static HTTP responses, 479,802 compressed body bytes and 489,805 bytes including HTTP/1 headers. That observation is an installation-window total and can include overlapping page requests. It must not be added to the cold foreground measurements. Browser cache policy, server compression and transport affect actual deployed bytes.

## Implementation and changed files

- apps/web/src/lib/{qr.ts,qrSvg.ts,useQr.tsx,useQr.test.tsx} isolate matrix encoding behind a same-origin import. SVG formatting is independently shareable. The hook reports pending/failure states, discards stale results and retains text controls.
- apps/web/src/components/{RecoveryKeyPanel,StaffRecoveryPanel,StatusHandoverPanel}.tsx and apps/web/src/pages/{StaffConsole,FacilityOverview}.tsx request encoding only when they have a QR to display. Recovery text and ordinary links render independently.
- apps/web/src/App.tsx and apps/web/src/pages/{TicketPage,RecoverPage}.tsx split join, ticket and recovery rendering. An eager route wrapper removes the browser fragment in a layout effect while handing React Router's in-memory copy to the route. Ticket resolution retains push-reference priority. apps/web/src/lib/tickets.ts drops the superseded fragment reader.
- apps/web/e2e/precache.spec.ts covers offline first use of QR and reload. apps/web/e2e/accessibility-m52.spec.ts waits for the asynchronously loaded join heading before traversing its links with a keyboard. Both the keyboard traversal and heading-focus requirements still execute.
- This report and docs/testing/M7-evidence.md record results. The implementation introduces no package dependency.

```sh
pnpm --filter @queuebridge/web exec vitest run src/lib/useQr.test.tsx src/lib/qr.test.ts
pnpm build
pnpm --filter @queuebridge/web bundle:check
pnpm lint
pnpm typecheck
pnpm format:check
pnpm test
pnpm test:db
pnpm --filter @queuebridge/web test:e2e --project=desktop-chromium --grep 'can first open the recovery QR|with no pointer at all|staff offline: connectivity'
pnpm --filter @queuebridge/web test:e2e
```

Workspace unit tests passed 1,143 cases and database tests passed 874. The new loader cases exercise a pending module, successful completion and a rejected import. An initial browser run exposed a staff hook below an early return and keyboard traversal beginning during the lazy fallback. The hook was moved above the return, and the keyboard test now establishes readiness before the interaction. The obsolete run was interrupted. All three focused browser regressions passed on the corrected build.

Final full local Playwright run: 369 passed, seven skipped, zero failed and zero timed out. The production build, existing bundle ceilings, repository formatting, lint and typecheck passed.
