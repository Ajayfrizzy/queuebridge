# Ticket-first feasibility

## Boundary recorded before implementation

Match the existing visitor paths within the same BrowserRouter. Render the existing VisitorRoute beneath the existing Layout. Load the remaining route tree only for its paths. Keep the common auth, offline, announcements and preferences providers mounted across transitions. Preserve the existing router fragment snapshot and synchronous layout-effect scrub before the ticket/recovery page chunk resolves. Keep pre-render display preferences and CSP-safe schema initialization, the service worker, stored ticket identity, revocation gates, access precedence and committed-turn listener. Continue using the existing API, IndexedDB and coordinator state ownership. Staff route components and their authorization wrappers can load together on entry. Authorization continues at the server. A cold visitor can be a signed-in staff member with pending operations; a pathname alone cannot authorize dropping coordinator state.

Measure the complete foreground including registration and all requested page dependencies. Exercise real visitor paths with the existing browser fixtures in a disposable database. A passing size result requires functional parity.

## Result

Hold production adoption. The route dispatcher preserves one live router and provider tree. It takes the shared entry from 137,511 to 133,296 gzip bytes. That entry by itself exceeds the complete-route allowance by 33,297 bytes.

Removing route definitions and screen implementations alone provides little leverage. Historical stripped-page builds also exceeded the budget before restoring full behavior.

The prototype changes App.tsx and adds OtherRoutes.tsx and e2e/ticket-first.spec.ts. The web production build and typecheck passed. Playwright desktop-chromium ran precache, precommit-regressions, recovery-url-secrecy, turn-alerts, offline-timing-handover and recovery suites: 41 passed. The added gated-import test and accessibility-m52 offline-accessibility group added six passes. Across both runs: 47 passed, zero failed or skipped. Coverage includes worker-enabled offline ticket reload, recovery QR, revoked access removing the offline copy, replay-safe server-confirmed turn alerts, push identity, fragment scrubbing during a delayed import, retry after failed import and refresh. No claim of full regression, translation parity or physical-device verification.

A larger experiment would have to separate anonymous reachability from authenticated coordinator initialization and isolate runtime contracts while preserving a single authenticated state owner. The remaining 46,076 bytes on ticket are substantial. The present experiment supplies no evidence that those changes would meet the budget safely. Keep this worktree for review and the production implementation on hold.
