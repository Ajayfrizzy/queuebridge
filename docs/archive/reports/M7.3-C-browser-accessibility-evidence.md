# M7.3-C browser and accessibility evidence

Local verification on feature/m7-3-hardening, base 5d2e5ea with accepted B4 work. Implements REQ-F15.8.1 and contributes to F15.6.1 and testing steering Group 15. Real-device acceptance F15.8.2 and recorded screen-reader review remain open.

## Executed automation

apps/web/e2e/browser-smoke.spec.ts has two journeys per engine and size. The first opens the landing page with reduced motion, changes theme, opens Ask Que with Enter, checks focus inside the panel, closes with Escape, verifies restored launcher focus, checks overflow, follows the sign-up CTA and runs axe on organization creation. The second provisions a real queue, joins, checks the ticket, recovers in a fresh visitor context, checks fragment removal, calls from a separately authenticated staff console and verifies the called state and turn alert. The two project sizes are 1280 × 800 and 375 × 812. A small viewport uses the same desktop engine. Device hardware, touch browser chrome and installed-app behavior require separate evidence.

apps/web/playwright.config.ts retains the Chromium regression and development StrictMode projects and scopes six additional projects to the smoke file. .github/workflows/ci.yml installs the three pinned engines. No hosted run was performed.

The existing accessibility-m52, accessibility, design-system, landing, header-controls, offline, recovery and que-ui specs exercise focus visibility and return, keyboard-only join and recovery, live-region updates, offline and validation errors, text-size preferences, reduced motion and high-contrast light/dark palettes. Responsive checks cover 320/375/768/1280/1440 CSS pixels. DOM and focus assertions establish observable announcement content. Audibility, timing and repetition still require a listening pass.

### Actual browser zoom

A local headless Chromium persistent profile loaded a temporary test extension with the tabs permission. With a 1280-pixel window the extension applied chrome.tabs.setZoom(tabId, 2) to the built preview and confirmed getZoom returned 2. Landing, sign-up and recovery each reported innerWidth = clientWidth = scrollWidth = 640 CSS pixels. Ask Que opened and closed on all three. API-backed workflows and physical controls at 200% remain on the human checklist.

Native macOS Firefox remains blocked.
