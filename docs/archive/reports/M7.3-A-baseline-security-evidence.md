## Clean web build and visitor budget

The workspace production build ran Vite with its normal in-root output directory cleanup. The existing checker read that fresh output and passed. Sizes are gzip -9 bytes.

| Asset            | Measured | Existing ceiling |
| ---------------- | -------: | ---------------: |
| Shared entry JS  |  195,504 |          197,241 |
| Shared entry CSS |    7,221 |            7,293 |
| Landing JS       |   24,725 |           26,647 |
| Landing CSS      |    3,044 |            3,348 |

The entry alone exceeds 100,000 bytes by 95,504. At least 95,505 bytes must leave the initial payload to achieve strictly less than 100 KB using decimal units, before counting other startup JS. Historically M7.1 measured 195,289 bytes and the prior audit inspected an existing build of 195,475 bytes. The large gap predates the landing page.

Source inspection of apps/web/src/App.tsx shows static imports of React Router, authentication, offline and accessibility providers, the shared layout, visitor join/recovery/ticket pages and staff console, connectivity, audit and administration screens. A visitor loads the common entry containing these static dependencies. LandingPage, QuePanel and publicKb have separate emitted assets. No per-module gzip contribution was established. apps/web/scripts/bundle-check.mjs measures four files, checks selected landing markers and HTML preload. It does not sum a route's dependency graph, measure runtime fetches, service-worker installation traffic or rendering latency. The broad JS/CSS glob in apps/web/src/pwa/swRules.ts can fetch lazy assets during installation.

## Findings, priorities and decisions for M7.3-B

1. **Monitoring exposure.** Confirmed application coverage gap, conditional availability risk. Both retained probes lack explicit application quotas. Readiness incurs DB work per request. Internet exposure, load impact and an exploitable deployment defect remain unverified. Prefer private monitoring ingress for readiness if RumptyCloud supports it. Otherwise propose a monitor-aware edge quota after checking health-check cadence, source attribution and replicas. Owner approval is needed for the ingress choice. Preserve liveness and legitimate monitoring.
2. **Visitor budget.** Preserve the approved absolute target. Propose route-level lazy loading of staff/admin screens first, then measure remaining framework, visitor and shared-provider costs. Obtain approval before restructuring provider or offline initialization. Measure cold initial route bytes and first-install traffic separately, and retain offline regression coverage.
3. **Rate-limit evidence.** Use controlled route-by-route boundary tests for the gaps above. Confirm trusted client addressing and replica behavior on the selected topology. No authorization bypass, unauthorized queue mutation or duplicate durable application was confirmed by the executed suites.
4. **Outstanding verification.** Capture route-level and Lighthouse measurements in the next authorized phase. The full regression matrix, hosted CI, live providers, real devices and RumptyCloud remain untested here. Existing historical M7 results remain separately attributed. No deployment or architecture decision follows from the local results.
