# Owner QA and Judge Demo

## Operator preparation

Use a reviewed, built release and the existing CA launcher on managed PostgreSQL. Supply the API runtime environment privately, including DEMO_DATABASE_NAME set to the expected database. Provisioning is an explicit CLI operation. The historical single-tenant seed remains available under its existing syntax.

Create an operator-owned directory outside all checkouts with mode 0700. Set PRIVATE_DEMO_DIR to that path. Generate each envelope once, import it into the appropriate private vault and supply it through stdin. Generation exclusively creates a mode-0600 file and refuses overwrite. Protect private copies and remove them after vault handoff. Each account signs in normally with the organization slug and the address formed as ROLE@PROFILE.example.invalid. Share individual judge entries through recipient-restricted vault access. Reserve the database runner and the Owner QA collection for the operator.

```sh
node infra/scripts/demo-credentials.js owner-qa "$PRIVATE_DEMO_DIR/owner.json"
node infra/scripts/demo-credentials.js judge-demo "$PRIVATE_DEMO_DIR/judge.json"
node infra/scripts/demo.js owner-qa seed < "$PRIVATE_DEMO_DIR/owner.json"
node infra/scripts/demo.js judge-demo seed < "$PRIVATE_DEMO_DIR/judge.json"
```

Save the printed facility ID and public join path. Each profile has a dedicated and a shared service desk configuration, two open queues and five fictional tickets. The initial states are three waiting (one priority), one called and one completed. Times and queue days follow Africa/Lagos. Repeated seeds return the marked facility. Open today's queues through normal workflows on subsequent days.

Only Judge Demo supports rotation. Pause use, bring every participating device online, sync and review pending work, verify each device has a fresh heartbeat, and close its console. A disconnected browser may hold newer work than the server can see. If any device cannot be accounted for, defer rotation. The operator supplies the drained current facility ID explicitly.

```sh
DEMO_DRAINED_FACILITY="$CURRENT_JUDGE_FACILITY" node infra/scripts/demo.js judge-demo reset "$CURRENT_JUDGE_FACILITY" < "$PRIVATE_DEMO_DIR/judge.json"
```

Distribute the replacement join path. Previous tickets, events and role grants remain available for historical audit. The operator command requires database access and authenticates the organization's administrator. Application accounts alone cannot invoke it.

## Optional judge walkthrough

Use separate browser profiles for the visitor and staff. Sign in to judge-demo for Willow Crossing. Independent exploration is available through the normal role menus and Ask Que.

1. As facility administrator, open Overview, inspect Registration and Consultation, both dedicated desks and Relief Desk. Scan the facility QR in the visitor profile, join Registration and privately save the key.
2. As reception, issue a walk-in. As counter staff, call the next eligible ticket, start service and complete it. Watch the visitor display and board when the visitor's own ticket is called.
3. As supervisor, inspect the priority reason, transfer a waiting ticket to an eligible service, designate a coordinator and review connectivity. Disconnect only that device, perform an authorized action, reconnect and inspect its disposition.
4. Recover the live visitor ticket in a fresh profile. For assisted recovery use reception as requester and a different eligible approver as required. As auditor, inspect queue history and verify the chain.
5. As organization administrator, explore facilities and staff management. Use Ask Que from each role. Explore display preferences, keyboard navigation and the channel availability screen. Use push only with device permission. SMS, USSD and optional AI follow the actual deployment capability manifest. Sandbox means test traffic. Use fictional records throughout.

## Local rehearsal

With a newly created empty, migrated loopback database named queuebridge_demo_rehearsal and NODE_ENV=test, run node infra/scripts/demo-rehearsal.js. It provisions both profiles concurrently, checks every role and cross-organization access, rotates Judge Demo and verifies ticket states and event chains. Rehearse real-device access, off-host backups, worker readiness, HTTPS, push and the private credential handoff separately before hosted activation.
